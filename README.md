# 複丈歷史資料匯出工具（網頁版）

將複丈案件資料夾（如 `KC0391`）內的 D 系列檔案（界址點／參考點／補點／地籍線／宗地）寫入固定名稱、
持續累積的彙整 GeoPackage（`QGIS\複丈歷史\複丈歷史.gpkg`），並確保 QGZ 專案檔的「複丈歷史」
群組下有這幾個固定圖層。每筆資料都標記 `CASE_ID`（格式：案號-民國年-月-日，例如
`KC0395-115-08-20`；舊圖加「-舊」後綴）記錄資料來源案件，所以處理過幾個案件，QGZ 裡的圖層數量永遠固定；
要看某個案件，用 `CASE_ID` 篩選即可。

**2.0.0 起改為網頁版（單一 .html 檔）**：到 [Releases](https://github.com/chenweihanfool/kc-survey-history-tool/releases)
下載 `kc-survey-history-tool.html`，用 Chrome 或 Edge 雙擊開啟就能使用，不必安裝、不需網路，
資料全程只在使用者自己的電腦上處理，不會上傳。原 Python／Tkinter 版移到 [`legacy/`](legacy/)，不再維護。

## 使用方式

1. 雙擊開啟下載的 `kc-survey-history-tool.html`（用 Chrome 或 Edge）。
2. **步驟 1**「選擇資料夾」：選「專案根目錄」（內含案件資料夾與 `QGIS` 資料夾），或直接選單一案件資料夾。
   - 選專案根目錄時，案件資料夾會列在「案件」下拉清單，並自動偵測 `QGIS` 資料夾與其中的 `.qgz`。
   - 第一次選擇時瀏覽器會要求授權讀寫該資料夾；下次可按「開啟上次的資料夾」。
   - 只選單一案件資料夾時，QGZ 可用「另選檔案…」指定，GPKG 輸出資料夾執行時會詢問。
   - **資料版本**：預設讀「新圖」（D14/D21/D13/D11，現況）；切換「舊圖」讀 D2C/D2D/D2B。
3. **步驟 2**「座標系統」：見下一節。
4. **步驟 3**：複丈日期（預設今天，用於 `CASE_ID`）。
5. **步驟 4**「輸出範圍」：全部地號，或指定地號（搜尋＋清單複選＋全選／清除）。
   補點／參考點／參考線不受地號篩選影響，由核取方塊控制「全部輸出」或「完全不輸出」。
6. **步驟 5**「開始輸出」：確認後寫入彙整 GPKG；若選了 QGZ，會先備份為 `.bak` 再更新專案。
   同一 `CASE_ID` 重跑會先刪除舊資料再寫入，不會重複累積。

點選畫面上方版本號可看更新歷程。

> **瀏覽器**：Chrome／Edge 可直接讀寫資料夾。Firefox／Safari 不支援直接寫入，仍可讀取與產生結果，
> 但 GPKG／QGZ 會以「下載」方式提供，需自行放回 `QGIS\複丈歷史`。

## TWD67 → TWD97 座標轉換

案件資料夾的座標預設視為 **TWD97**（EPSG:3826），不做任何轉換。若案件是 **TWD67**：

1. 步驟 2 選「TWD67（轉成 TWD97 後輸出）」。
2. 從「轉換參數」下拉清單選一組參數（各地區各自一組）。
3. 輸出的 GPKG 一律是 TWD97；界址點、參考點、補點（連同由它們組成的線與宗地）都會轉換。

### 轉換參數＝INP 控制點檔

每個 INP 檔是一組參數，每行：

```
點名  類型  TWD97北  TWD97東  TWD67北  TWD67東
A4    1     2709376.350  218785.951  2709581.598  217956.883
```

前 2 欄是 TWD97、後 2 欄是 TWD67 公告座標。只有一組座標的點（如 `N114026  8  2709412.362  218175.238`）
不能當控制點，匯入時自動略過；座標明顯不合理的列也會略過。

**一次吃進所有參數**：按「管理轉換參數…」：

- 「匯入 INP 檔」可一次多選；「匯入整個資料夾」會抓資料夾內全部 `.inp`；
- 「匯出設定檔／匯入設定檔」把整包參數存成一個 JSON，帶到另一台電腦或另一個瀏覽器；
- 案件資料夾內若本身就有 `.inp`，主畫面會提示「匯入為轉換參數」。

參數存在這個瀏覽器（`localStorage`），之後每次只要在主畫面下拉選擇。同名參數匯入視為更新。
（`file://` 開啟的單檔共用瀏覽器的 file 儲存空間；換電腦或換瀏覽器請用「匯出設定檔」帶過去。）

### 轉換方法與精度

- 預設用控制點做**最小二乘 6 參數仿射**擬合（可在管理畫面改成 4 參數相似轉換或僅平移）。
  控制點不足或共線時自動退回較簡單的模型並提示。
- 與控制點座標相符（±0.5 mm）的點，直接採用公告的 TWD97 值（可在管理畫面取消「用公告值」）。
- 管理畫面會顯示殘差 RMS／最大值與每個控制點的殘差。非控制點的實際誤差要看「留一法」：
  以 33 組控制點的範例，殘差 RMS 3.3 cm，留一法預期誤差約 3.6 cm（最大約 7 cm）。
- 轉換前自動檢查並在確認視窗提醒：資料看起來已經是 TWD97、案件離控制點太遠、
  點位超出控制點範圍 1 km 以上（外插）。
- 座標的北／東欄位順序由數值大小自動判斷（北約 2,400,000～2,800,000、東約 100,000～350,000）。

## 發布與自動更新（GitHub Release）

- **發布**：`.github/workflows/release.yml` 在 `master` 更新、且 [`site/js/version.js`](site/js/version.js) 的
  `APP_VERSION` 還沒有對應 Release 時，自動跑測試、打包成單一 `kc-survey-history-tool.html`（所有 JS 與
  sql.js 的 WASM 都內嵌）、建立 GitHub Release（tag `v<版號>`，說明取自 `CHANGELOG` 最新一筆）並附上檔案。
  版號沒變就什麼都不做。
- **發布新版的步驟**：調整 `APP_VERSION`、在 `CHANGELOG` 補上說明，合併 PR，其餘自動完成。
- **自動更新**：頁面啟動時查詢 `releases/latest`，若比目前版本新，頁面上方會提示並提供新版 `.html` 的下載連結。
  檔案無法自己覆蓋自己，所以由使用者用新檔取代舊檔。轉換參數存在瀏覽器的 `localStorage`，換檔通常會保留，
  建議先在「管理轉換參數」匯出設定檔備份。
- **本機打包**：`npm ci && node scripts/build.mjs`，輸出 `dist/kc-survey-history-tool.html`。

舊版 exe（1.x）的自動更新只認 Release 附件裡的 `.exe`；網頁版 Release 不附 exe，舊版 exe 會安靜地不更新、照常使用。

## 開發與測試

```bash
npm test                       # 單元測試 + 與舊版 Python 輸出逐列對照（需要 python3、node 22）
python3 -m http.server -d site # 開發預覽（未打包版）：http://localhost:8000
node scripts/build.mjs         # 打包單一 .html
```

- `tests/parity.test.mjs`：用合成案件資料，確認 JS 版輸出的 GPKG 與 `legacy/` Python 版逐列一致
  （新圖、舊圖、指定地號、不含補點、重跑取代）。
- `tests/twd.test.mjs`：INP 解析、擬合、套用、安全檢查、參數庫。
- 模組：`dbf.js`（DBF 讀取）、`survey.js`（案件解析與圖層）、`gpkg.js`（GPKG 讀寫）、`qgz.js`（QGZ 修改）、
  `twd.js`（座標轉換）、`workspace.js`（檔案存取）、`pipeline.js`（匯出流程）、`update.js`、`app.js`（畫面）。

## 資料來源與判讀邏輯

- 預設座標系統為 TWD97 / TM2 zone 121（EPSG:3826），輸出的 GPKG 一律是此座標系。
- **新圖（預設）**：點位用 D14、地籍線用 D21、宗地邊界用 D13、宗地面積／地目用 D11。
- **舊圖**：點位用 D2C、地籍線用 D2D、宗地邊界用 D2B；沒有面積／地目。新舊圖是各自獨立的資料集，不互相合併。
- 地籍線所有段別合併為單一圖層，以 `L_SEC`／`R_SEC` 區分段別。
- 補點（D20）／參考線（D29）新舊圖共用。參考線端點若找不到精確對應的參考點座標，直接跳過該線段，
  不退回連到錯誤的點位（曾造成參考線整片交叉打結，FG0518 案件）。
- 補點另有 `STATE` 屬性（0=良好 ?=未知 x=已回報找不到，預設 ?）；既有 GPKG 缺欄位時自動遷移補上。

`docs/` 內的操作說明書是 1.x（exe）版的，網頁版的差異以本文件為準。
